    code/data.py 
    """Stage 0: data for the regression deliverable — reuses the EDA pipeline.

Same split as the EDA (80/20, seed 42). The validation set is carved out of the
EDA training set; the preprocessor is fitted on the remaining training rows only.

The test set is only returned when asked for (`with_test=True`), which must
happen once, in Stage 5 (evaluate.py).
"""

import sys
from pathlib import Path

import numpy as np
import pandas as pd
from sklearn.metrics import mean_absolute_error, r2_score, root_mean_squared_error
from sklearn.model_selection import train_test_split

# The EDA pipeline is imported, not copied.
sys.path.insert(0, str(Path(__file__).resolve().parents[2] / "eda" / "code"))
from pipeline import (  # noqa: E402
    N_PRICE_BINS, SEED, build_preprocessor, load_split, transform_target,
)

VAL_SIZE = 0.2  # fraction of the EDA training set held out for validation

CODE_DIR = Path(__file__).resolve().parent
FIG_DIR = CODE_DIR.parent / "figures"


def load_data(with_test=False):
    """Return a dict with preprocessed features and targets.

    Keys: X_train, X_val (float32 arrays), y_train, y_val (price in US$, arrays),
    raw_train, raw_val (original feature frames, for subgroup analysis),
    feature_names and the fitted preprocessor `pre`.
    With `with_test=True`, also X_test, y_test and raw_test.
    """
    X_full, X_test, y_full, y_test = load_split()
    strata = pd.qcut(np.log1p(y_full), q=N_PRICE_BINS, labels=False, duplicates="drop")
    X_train, X_val, y_train, y_val = train_test_split(
        X_full, y_full, test_size=VAL_SIZE, random_state=SEED, stratify=strata
    )
    pre = build_preprocessor().fit(X_train)  # fit on train only
    data = {
        "X_train": pre.transform(X_train).astype(np.float32),
        "X_val": pre.transform(X_val).astype(np.float32),
        "y_train": y_train.to_numpy(dtype=float),
        "y_val": y_val.to_numpy(dtype=float),
        "raw_train": X_train,
        "raw_val": X_val,
        "feature_names": list(pre.get_feature_names_out()),
        "pre": pre,
    }
    if with_test:
        data["X_test"] = pre.transform(X_test).astype(np.float32)
        data["y_test"] = y_test.to_numpy(dtype=float)
        data["raw_test"] = X_test
    return data


def to_log(price):
    """Model target: log1p(price), as decided in the EDA."""
    return np.asarray(transform_target(price), dtype=np.float32)


def to_price(log_pred):
    """Invert the target transform: back to US$."""
    return np.expm1(np.asarray(log_pred, dtype=float))


def regression_metrics(price_true, price_pred):
    """Metrics on the original scale (US$). MAE is the main metric."""
    return {
        "mae": float(mean_absolute_error(price_true, price_pred)),
        "rmse": float(root_mean_squared_error(price_true, price_pred)),
        "r2": float(r2_score(price_true, price_pred)),
        "rmse_log": float(root_mean_squared_error(
            np.log1p(price_true), np.log1p(np.clip(price_pred, 0, None))
        )),
    }

    What changed since the EDA, and why:

    Change Reason
    A validation set is taken from the EDA training set: 20% of it, stratified by log1p(price) quintile (same rule as the train/test split), seed 42 every choice in Stages 1–4 is made on validation, so the test set is used only once, in Stage 5

    The model sees 91 features instead of 102 consequence of the line above: with fewer training rows, only 75 neighbourhoods (instead of 86) reach the 50-listing minimum; the others fall into neighbourhood_infrequent_sklearn. 91 = 7 numerical + 5 boroughs + 76 neighbourhood columns + 3 room types
    The test set is only loaded with load_data(with_test=True) prevents an accidental use of the test set before Stage 5

    There are 0 NaN after the pipeline in train and validation.

    Target. The network predicts log1p(price) (EDA, Stage 1C: skewness 19.22 → 0.64). Every metric below is computed in US$, after inverting with expm1.

    **Main metric: MAE in US\(**, on the original scale. Reasons: (1) it reads directly as "the prediction is off by US\) X per night on average"; (2) the EDA showed a price tail up to US$ 10,000, and RMSE and R² in US$ are dominated by those few listings, so they would mostly measure the luxury tail and not the typical listing. RMSE and R² are still reported, as required.

    Success criterion, set before training any network: the network's MAE on the test set must be at least 5% lower than the MAE of the best baseline on the same test set. Why 5% and not more: the EDA found little signal (largest |ρ| with the target is 0.44) and the strongest effects — room type and borough — are additive in log scale, which a linear model already captures. What is left for the network is the nonlinear part: the price surface over latitude × longitude and its interaction with room type (EDA, Figure 5).

    1 · Baselines

    Both baselines use the same pipeline and the same target as the network: fitted on log1p(price) with the 91 features, predictions converted back to US$, evaluated on the validation set.

    • Trivial: DummyRegressor(strategy="mean") — predicts the training mean of log1p(price) for every listing.
    • Linear: Ridge(alpha=1.0) — linear regression with L2, because the 76 one-hot neighbourhood columns are sparse and correlated with the borough columns.

from sklearn.linear_model import Ridge

def build_baselines():
    return {
        "dummy_mean": DummyRegressor(strategy="mean"),
        "ridge": Ridge(alpha=1.0),
    }


def fit_baselines(X_train, y_train):
    """Fit every baseline on log1p(price). Returns {name: fitted model}."""
    y_log = to_log(y_train)
    return {name: m.fit(X_train, y_log) for name, m in build_baselines().items()}

    OUT_JSON.write_text(json.dumps(numbers, indent=2))

    • In log scale Ridge is much better than its R² in US$ suggests: the RMSE in log drops from 0.687 to 0.458, which is 55.5% of the variance of log1p(price) explained (1 − 0.458² / 0.687²).     2 · The network

    MLP in PyTorch, in code/model.py.

    flowchart LR
    x["Input<br/>91 features"] --> h1["Linear 128<br/>ReLU"]
    h1 --> h2["Linear 64<br/>ReLU"]
    h2 --> out["Linear 1<br/>(no activation)"]
    Choice Why
    Hidden layers 2 one hidden layer can already bend the linear solution; the second lets the network combine location with room type, the interaction the EDA pointed to. Other depths are tested in Stage 4
    Widths 128 → 64 first layer wider than the input (91) so that the sparse one-hot columns are not squeezed right away; then it narrows towards the single output
    Activation ReLU cheap, does not saturate for positive inputs, standard for tabular MLPs
    Initialization He (Kaiming) normal, biases at 0 designed for ReLU: keeps the variance of the activations stable from layer to layer
    Output 1 linear unit regression: log1p(price) is an unbounded real number, so no activation
    Loss Huber (δ = 1) on log1p(price) see below

    Loss, justified by the EDA outliers. Even after the log, the target keeps a right tail (skewness 0.64; 2.17% of the EDA training listings cost more than US$ 500) that the features do not explain. With MSE, those few listings would produce the largest gradients. Huber is quadratic for errors below 1 log unit (a factor of about 2.7 in price) and linear above that, so ordinary listings are treated as in MSE and the tail is treated as in MAE — which also matches the main metric.

    Size. The network has 20,097 parameters (91·128 + 128 = 11,776; 128·64 + 64 = 8,256; 64 + 1 = 65) for 31,285 training rows — 0.64 parameter per row. It has far more capacity than Ridge (92 parameters) and could overfit, so early stopping (Stage 3) and regularization (Stage 4) are needed, but it still has fewer parameters than training rows.

    code/model.py 
    """Stage 2: the network — an MLP for regression on log1p(price)."""

import torch
from torch import nn


class MLP(nn.Module):
    """Linear -> [BatchNorm] -> ReLU -> [Dropout] per hidden layer, then one linear unit.

    The output is linear (no activation): the target log1p(price) is unbounded.
    """

    def __init__(self, n_in, hidden=(128, 64), dropout=0.0, batchnorm=False):
        super().__init__()
        layers = []
        width = n_in
        for units in hidden:
            layers.append(nn.Linear(width, units))
            if batchnorm:
                layers.append(nn.BatchNorm1d(units))
            layers.append(nn.ReLU())
            if dropout > 0:
                layers.append(nn.Dropout(dropout))
            width = units
        layers.append(nn.Linear(width, 1))
        self.net = nn.Sequential(*layers)
        self.apply(self._init)

    @staticmethod
    def _init(module):
        # He initialization: keeps the activation variance stable through ReLU layers.
        if isinstance(module, nn.Linear):
            nn.init.kaiming_normal_(module.weight, nonlinearity="relu")
            nn.init.zeros_(module.bias)

    def forward(self, x):
        return self.net(x).squeeze(-1)


def count_parameters(model):
    return sum(p.numel() for p in model.parameters() if p.requires_grad)

    3 · Training

    The loop is train_model in code/train.py; Stages 4 and 5 reuse the same function.

    Choice Why
    Optimizer Adam (AdamW with weight_decay=0) adapts the step per parameter, which matters here: the one-hot columns of rare neighbourhoods get a gradient in very few batches, while the 7 numerical features get one in every batch. Using AdamW lets Stage 4 turn on weight decay without changing the code
    Learning rate 1e-3 compared with 1e-2 and 1e-4 below (Figure 2)
    Batch size 256 123 updates per epoch on 31,285 rows: enough updates to converge in few epochs, with batches large enough for a stable curve
    Maximum epochs 200 only an upper limit; early stopping decides
    Early stopping patience 15 on the validation loss, best weights restored the validation loss oscillates between epochs (Figure 1), so stopping at the first bad epoch would stop on noise; 15 epochs separates noise from a real upward trend
    code/train.py 
    """Stage 3: training loop with early stopping, learning curves and the LR comparison.

Run from the repository root:  python docs/projects/regression/code/train.py
Produces Figures 1 and 2 and train_numbers.json. Uses train and validation only.

`train_model` is the single training entry point reused by Stages 4 and 5.
"""

import copy
import json

import matplotlib

matplotlib.use("Agg")
import matplotlib.pyplot as plt  # noqa: E402
import numpy as np  # noqa: E402
import torch  # noqa: E402
from torch import nn  # noqa: E402

from data import (  # noqa: E402
    CODE_DIR, FIG_DIR, SEED, load_data, regression_metrics, to_log, to_price,
)
from model import MLP, count_parameters  # noqa: E402

OUT_JSON = CODE_DIR / "train_numbers.json"

# Base configuration: no regularization. Stage 4 overrides keys of this dict.
BASE_CONFIG = {
    "hidden": (128, 64),
    "dropout": 0.0,
    "batchnorm": False,
    "weight_decay": 0.0,
    "optimizer": "adamw",   # with weight_decay=0, AdamW is plain Adam
    "lr": 1e-3,
    "batch_size": 256,
    "max_epochs": 200,
    "patience": 15,
    "loss": "huber",
}
LR_GRID = [1e-2, 1e-3, 1e-4]

LOSSES = {"huber": nn.HuberLoss, "mse": nn.MSELoss, "mae": nn.L1Loss}


def make_optimizer(model, cfg):
    if cfg["optimizer"] == "sgd":
        return torch.optim.SGD(model.parameters(), lr=cfg["lr"], momentum=0.9,
                               weight_decay=cfg["weight_decay"])
    return torch.optim.AdamW(model.parameters(), lr=cfg["lr"],
                             weight_decay=cfg["weight_decay"])


def train_model(X_train, y_train_log, X_val, y_val_log, config=None, seed=SEED):
    """Train an MLP with early stopping on the validation loss.

    Returns (model with the best weights restored, history dict).
    history: train_loss and val_loss per epoch, best_epoch (1-based), stopped_epoch.
    """
    cfg = {**BASE_CONFIG, **(config or {})}
    torch.manual_seed(seed)
    X_tr, y_tr = torch.as_tensor(X_train), torch.as_tensor(y_train_log)
    X_va, y_va = torch.as_tensor(X_val), torch.as_tensor(y_val_log)

    model = MLP(X_tr.shape[1], cfg["hidden"], cfg["dropout"], cfg["batchnorm"])
    optimizer = make_optimizer(model, cfg)
    loss_fn = LOSSES[cfg["loss"]]()

    history = {"train_loss": [], "val_loss": []}
    best_val, best_state, best_epoch, bad_epochs = float("inf"), None, 0, 0
    for epoch in range(1, cfg["max_epochs"] + 1):
        model.train()
        order = torch.randperm(len(X_tr))
        total = 0.0
        for start in range(0, len(order), cfg["batch_size"]):
            idx = order[start:start + cfg["batch_size"]]
            optimizer.zero_grad()
            loss = loss_fn(model(X_tr[idx]), y_tr[idx])
            loss.backward()
            optimizer.step()
            total += loss.item() * len(idx)

        model.eval()
        with torch.no_grad():
            val_loss = loss_fn(model(X_va), y_va).item()
        history["train_loss"].append(total / len(X_tr))
        history["val_loss"].append(val_loss)

        if val_loss < best_val:
            best_val, best_epoch, bad_epochs = val_loss, epoch, 0
            best_state = copy.deepcopy(model.state_dict())
        else:
            bad_epochs += 1
            if bad_epochs >= cfg["patience"]:
                break

    model.load_state_dict(best_state)  # restore the best weights
    history["best_epoch"] = best_epoch
    history["stopped_epoch"] = epoch
    return model, history


def predict_price(model, X):
    """Predictions in US$ (inverse of log1p)."""
    model.eval()
    with torch.no_grad():
        return to_price(model(torch.as_tensor(X)).numpy())


def plot_learning_curves(history, name):
    epochs = np.arange(1, len(history["train_loss"]) + 1)
    fig, ax = plt.subplots(figsize=(7, 4))
    ax.plot(epochs, history["train_loss"], label="train")
    ax.plot(epochs, history["val_loss"], label="validation")
    ax.axvline(history["best_epoch"], color="gray", ls="--",
               label=f"best epoch ({history['best_epoch']})")
    ax.set(title="Huber loss on log1p(price) per epoch — base network",
           xlabel="epoch", ylabel="Huber loss (log scale)", yscale="log")
    ax.legend()
    fig.tight_layout()
    fig.savefig(FIG_DIR / name, dpi=110)
    plt.close(fig)


def plot_lr_comparison(histories, name):
    fig, ax = plt.subplots(figsize=(7, 4))
    for lr, h in histories.items():
        ax.plot(np.arange(1, len(h["val_loss"]) + 1), h["val_loss"], label=f"lr = {lr:g}")
    ax.set(title="Validation loss per epoch for three learning rates",
           xlabel="epoch", ylabel="validation Huber loss", yscale="log")
    ax.legend()
    fig.tight_layout()
    fig.savefig(FIG_DIR / name, dpi=110)
    plt.close(fig)


def main():
    d = load_data()
    y_tr, y_va = to_log(d["y_train"]), to_log(d["y_val"])

    numbers = {"config": BASE_CONFIG, "lr_comparison": {}}

    best = base_h["best_epoch"] - 1
    numbers["base"] = {

        "train_rows": len(y_tr),
        "best_epoch": base_h["best_epoch"],
        "stopped_epoch": base_h["stopped_epoch"],
        "train_loss_at_best": base_h["train_loss"][best],
        "val_loss_at_best": base_h["val_loss"][best],
        "train_loss_last": base_h["train_loss"][-1],
        "val_loss_last": base_h["val_loss"][-1],
        "train_loss": base_h["train_loss"],
        "train": regression_metrics(d["y_train"], predict_price(base_model, d["X_train"])),
        "val": regression_metrics(d["y_val"], predict_price(base_model, d["X_val"])),
    }
    plot_learning_curves(base_h, "fig01-learning-curves.png")
    plot_lr_comparison(histories, "fig02-lr-comparison.png")
    OUT_JSON.write_text(json.dumps(numbers, indent=2))
    print(json.dumps(numbers, indent=2))

    4 · Regularization and hyperparameters

    Everything in this stage uses train and validation only: code/search.py calls load_data() without the test set and trains every configuration with train_model from Stage 3 (same Huber loss, batch 256, early stopping with patience 15).

    Five seeds per configuration, not one. Stage 3 used a single seed. Repeating the base network with seeds 42 to 46 (the seed changes weight initialization and batch order; the split stays fixed) gives a validation MAE of 55.84 ± 0.21 (mean ± sample standard deviation). Most of the differences between configurations below are of a few tenths of a dollar — the same order as this standard deviation — so a single seed would rank noise. Every configuration is therefore trained 5 times and ranked by its mean validation MAE. (With seed 42 alone the base network gives 55.55 here against 55.57 in Stage 3, with the same best and stopping epochs, 18 and 33: the difference is floating-point arithmetic across machines.)

    code/search.py

def add_availability_flag(X, raw):
    """EDA promise: append the binary flag availability_365 == 0 as a 92nd column."""
    flag = (raw["availability_365"].to_numpy() == 0).astype(np.float32)
    return np.column_stack([X, flag])


def label(overrides):
    """Readable description of a configuration, e.g. '256-128 · lr 1e-3 · dropout 0.2'."""
    cfg = {**BASE_CONFIG, **overrides}
    parts = ["-".join(str(u) for u in cfg["hidden"]), f"lr {cfg['lr']:g}"]
    if cfg["dropout"] > 0:
        parts.append(f"dropout {cfg['dropout']:g}")
    if cfg["weight_decay"] > 0:
        parts.append(f"wd {cfg['weight_decay']:g}")
    if cfg["batchnorm"]:
        parts.append("BatchNorm")
    return " · ".join(parts)


def summarize(runs):
    """Mean and sample std (ddof=1) over seeds of every metric in the runs."""
    keys = [k for k in runs[0] if k != "seed"]
    mean = {k: float(np.mean([r[k] for r in runs])) for k in keys}
    std = {k: float(np.std([r[k] for r in runs], ddof=1)) for k in keys}
    return mean, std


def evaluate_config(X_tr, X_va, d, overrides):
    """Train one configuration with every seed; return per-seed validation results."""
    y_tr, y_va = to_log(d["y_train"]), to_log(d["y_val"])
    runs = []
    for seed in SEEDS:
        model, h = train_model(X_tr, y_tr, X_va, y_va, overrides, seed)
        metrics = regression_metrics(d["y_val"], predict_price(model, X_va))
        runs.append({"seed": seed, **metrics,
                     "best_epoch": h["best_epoch"], "stopped_epoch": h["stopped_epoch"]})
    return runs


def run_configs(specs, X_tr, X_va, d):
    results = []
    for name, group, overrides in specs:
        runs = evaluate_config(X_tr, X_va, d, overrides)
        mean, std = summarize(runs)
        cfg = {**BASE_CONFIG, **overrides}
        n_params = count_parameters(MLP(X_tr.shape[1], cfg["hidden"], cfg["dropout"],
                                        cfg["batchnorm"]))
        results.append({"name": name, "group": group, "label": label(overrides),
                        "overrides": overrides, "parameters": n_params,
                        "mean": mean, "std": std, "runs": runs})
        print(f"{name:26s} MAE {mean['mae']:.2f} ± {std['mae']:.2f}")
    return results


def flag_comparison(d, base_result):
    """Base network and Ridge with and without the availability flag."""
    X_tr = add_availability_flag(d["X_train"], d["raw_train"])
    X_va = add_availability_flag(d["X_val"], d["raw_val"])

    ridge_flag = fit_baselines(X_tr, d["y_train"])["ridge"]
    ridge = {

        "with": regression_metrics(d["y_val"], to_price(ridge_flag.predict(X_va))),
    }
    return with_flag, {

    4A · Each regularization technique alone

    Same base network (128 → 64, learning rate 1e-3); one change at a time, two strengths for weight decay and for dropout:

    Technique Setting Validation MAE (US$) Δ vs base Mean best epoch
    None (base) — 55.84 ± 0.21 — 25.2
    Weight decay (AdamW) 0.01 55.81 ± 0.18 −0.02 25.2
    Weight decay (AdamW) 0.1 55.65 ± 0.12 −0.19 28.0
    Dropout 0.1 55.39 ± 0.23 −0.44 65.2
    Dropout 0.3 55.63 ± 0.25 −0.21 96.6
    BatchNorm after each linear layer 55.93 ± 0.35 +0.10 24.4

    Why these settings: in AdamW the decay is decoupled from the gradient, and each step shrinks the weights by a factor of lr × weight_decay (1e-5 or 1e-4 per step here), so 0.01 and 0.1 go from weak to moderate. Dropout 0.1 and 0.3 bracket the usual range for a network this narrow (64 units in the last hidden layer).

    Reading.

    • Dropout is the only technique with a clear effect on its own: 0.1 lowers the MAE by 0.44, about twice the seed standard deviation. It also makes training longer (best epoch 65.2 against 25.2): the noise it injects slows down the fit to the training set, and the validation loss keeps improving for more epochs.
    • More dropout is worse on this small network (0.3: −0.21 only): removing 30% of 64 units takes away capacity the network needs. Section 4C shows that the same 0.3 works well once the network is wider.
    • Weight decay barely matters: 0.01 changes the MAE by 0.02 (a tenth of the seed standard deviation); 0.1 lowers it by 0.19, still within the noise.
    • BatchNorm makes it slightly worse (+0.10) and is the least stable of the six (std 0.35). The pipeline already standardizes every input and the network has only two hidden layers, so there is no conditioning problem for BatchNorm to fix; what it adds is noise from the batch statistics.
    • This agrees with Stage 3: the base network was not limited by overfitting (small gap between the training and validation curves), so regularizing it changes little. Where regularization matters is when the capacity grows: the 256 → 128 network without regularization is the worst of all configurations below (56.13 ± 0.40; it peaks at epoch 19.0), and with dropout 0.2 the same network drops to 55.38 ± 0.13.

    Reading Figure 3 and the table.

    • What wins is capacity with regularization. The top 3 all have 3 hidden layers and dropout of 0.2 or more. Without regularization, more width hurts: 256 → 128 alone is last (56.13), and the same network with dropout 0.2 is eighth (55.38).
    • The learning rate of Stage 3 holds. Around 256 → 128 with dropout 0.2, both 3e-3 (55.53) and 3e-4 (55.54) are worse than 1e-3 (55.38).
    • Round 2 found a plateau, which is why the search stops there. Going from dropout 0.3 to 0.4 changes nothing (55.09 and 55.09). Doubling the width (55.23) or adding a fourth layer (55.32) does not help and makes the result less stable (std 0.32 and 0.40).

    5 · Test evaluation

    Script: code/evaluate.py.

    How the test set was used — once.

    1. Everything was fixed before the test set was loaded: the configuration (best_config.json, Stage 4), the seeds (42 to 46), the metrics, the figures and the decision rule for the criterion (mean test MAE over the 5 seeds against the best baseline's test MAE).
    2. The script was developed on validation: without arguments, evaluate.py runs the whole evaluation on the validation set and writes nothing. That run reproduced Stage 4 exactly (55.09 ± 0.15), which confirms that retraining is deterministic. The figure and CSV code was also checked on validation predictions.
    3. Then the script ran once with --split test — the only time Stages 0 to 5 loaded the test set (load_data(with_test=True)). Nothing was changed after it — no configuration, seed, threshold or figure choice was influenced by the test set. Running the command again reproduces the same numbers; it is not a new decision.

    Protocol. For each seed, the chosen network is trained from scratch on the 31,285 training rows, with early stopping on validation — the same protocol under which it was selected. It is not retrained on train + validation, because early stopping needs the validation set and the number of epochs would otherwise have to be guessed. def train_seeds(d, config, X_eval, y_eval):
    """Retrain the chosen configuration once per seed; early stopping on validation."""
    y_tr, y_va = to_log(d["y_train"]), to_log(d["y_val"])
    runs, preds, n_params = [], {}, None
    for seed in SEEDS:
        model, h = train_model(d["X_train"], y_tr, d["X_val"], y_va, config, seed)
        preds[seed] = predict_price(model, X_eval)
        n_params = count_parameters(model)
        runs.append({"seed": seed, **regression_metrics(y_eval, preds[seed]),
                     "best_epoch": h["best_epoch"], "stopped_epoch": h["stopped_epoch"]})
    return runs, preds, n_params


def criterion(mean, std, runs, baselines):
    """Stage 0 criterion and the gap to the best baseline against the seed variation."""
    best_name = min(baselines, key=lambda k: baselines[k]["mae"])
    base_mae = baselines[best_name]["mae"]
    gap = base_mae - mean["mae"]
    return {
        "best_baseline": best_name,
        "best_baseline_mae": base_mae,
        "threshold_mae": (1 - TARGET_GAIN) * base_mae,
        "gain_mean": 1 - mean["mae"] / base_mae,
        "gain_per_seed": {str(r["seed"]): 1 - r["mae"] / base_mae for r in runs},
        "seeds_meeting_criterion": sum(r["mae"] <= (1 - TARGET_GAIN) * base_mae for r in runs),
        "met": bool(mean["mae"] <= (1 - TARGET_GAIN) * base_mae),
        "gap_mae": gap,
        "gap_over_seed_std": gap / std["mae"],
        "worst_seed_mae": max(r["mae"] for r in runs),
        "all_seeds_beat_baseline": all(r["mae"] < base_mae for r in runs),
    }


def residual_summary(y_true, y_pred):
    """Bias of the predictions, overall and per quintile of the predicted price."""
    res = y_true - y_pred
    bins = pd.qcut(y_pred, q=N_RESIDUAL_BINS)
    per_bin = pd.DataFrame({"res": res, "bin": bins}).groupby("bin", observed=True)["res"]
    return {
        "mean_residual": float(res.mean()),
        "median_residual": float(np.median(res)),
        "share_underpredicted": float((res > 0).mean()),
        "mean_log_residual": float(np.mean(np.log1p(y_true) - np.log1p(y_pred))),
        "by_predicted_quintile": [
            {"pred_from": float(b.left), "pred_to": float(b.right),
             "median_residual": float(g.median()), "mean_residual": float(g.mean())}
            for b, g in per_bin
        ],
    }

def build_frame(raw, y_true, y_pred, y_ridge=None):
    """Original features plus the true price, the prediction and the signed error."""
    df = raw.copy()
    df["price_true"] = np.asarray(y_true, dtype=float)
    df["price_pred"] = np.asarray(y_pred, dtype=float)
    df["error"] = df["price_pred"] - df["price_true"]
    df["abs_error"] = df["error"].abs()
    if y_ridge is not None:
        df["price_ridge"] = np.asarray(y_ridge, dtype=float)
        df["abs_error_ridge"] = (df["price_ridge"] - df["price_true"]).abs()
    return df


def stats(part, total):
    """MAE in US$ and the numbers needed to read it: size, price level and bias."""
    if len(part) == 0:
        return {"n": 0, "share_pct": 0.0, "mae": None, "bias": None,
                "mean_price": None, "mae_pct_of_price": None}
    mae = float(part["abs_error"].mean())
    mean_price = float(part["price_true"].mean())
    out = {
        "n": int(len(part)),
        "share_pct": round(100 * len(part) / total, 2),
        "mae": mae,
        "bias": float(part["error"].mean()),
        "mean_price": mean_price,
        "mae_pct_of_price": round(100 * mae / mean_price, 1),
    }
    if "abs_error_ridge" in part.columns:
        mae_ridge = float(part["abs_error_ridge"].mean())
        out["mae_ridge"] = mae_ridge
        out["gain_vs_ridge_pct"] = round(100 * (mae_ridge - mae) / mae_ridge, 1)
    return out


def subgroup_rows(df, column):
    """One row per level of a categorical column, sorted by MAE (largest first)."""
    rows = [{"group": str(level), **stats(part, len(df))}
            for level, part in df.groupby(column, observed=True)]
    return sorted(rows, key=lambda r: -(r["mae"] or 0))


def price_band_rows(df):
    """Quintiles of the true price, in order, plus the luxury tail as an extra row."""
    bands = pd.qcut(df["price_true"], q=PRICE_BINS, duplicates="drop")
    rows = []
    for i, (interval, part) in enumerate(df.groupby(bands, observed=True)):
        low = df["price_true"].min() if i == 0 else interval.left
        rows.append({"band": f"US$ {low:.0f}-{interval.right:.0f}", **stats(part, len(df))})
    tail = df[df["price_true"] > TAIL_PRICE]
    rows.append({"band": f"tail: > US$ {TAIL_PRICE}", **stats(tail, len(df))})
    return rows


def availability_rows(df):
    """The 'availability_365 == 0' flag the EDA found on a third of the listings."""
    zero = df["availability_365"] == 0
    return [
        {"group": "availability_365 == 0", **stats(df[zero], len(df))},
        {"group": "availability_365 > 0", **stats(df[~zero], len(df))},
    ]


def worst_rows(df, n):
    """The n largest absolute errors, with the original features."""
    cols = ["price_true", "price_pred", "abs_error", "room_type", "neighbourhood_group",
            "neighbourhood", "minimum_nights", "number_of_reviews", "reviews_per_month",
            "calculated_host_listings_count", "availability_365", "latitude", "longitude"]
    worst = df.sort_values("abs_error", ascending=False).head(n)
    out = []
    for row_index, row in worst[cols].iterrows():
        record = {"row_index": int(row_index)}
        for col in cols:
            value = row[col]
            record[col] = value if isinstance(value, str) else float(value)
        out.append(record)
    return out


def largest_error_group(subgroups, families, min_n=0):
    """The group with the largest MAE among the given families — summary row 8."""
    best = None
    for family in families:
        for row in subgroups[family]:
            label = row.get("group") or row.get("band")
            if row["mae"] is None or row["n"] < min_n:
                continue
            if best is None or row["mae"] > best["mae"]:
                best = {"family": family, "group": label, "mae": row["mae"],
                        "n": row["n"], "mean_price": row["mean_price"]}
    return best

def permutation_importance(model, pre, raw, y_true, n_repeats, seed=SEED):
    """Increase in validation MAE when one ORIGINAL column is shuffled.

    The 10 columns of the raw frame are shuffled one at a time and pushed through the
    fitted preprocessor, so one shuffle moves every one-hot column that the feature
    produces (76 of the 91 model columns come from `neighbourhood` alone).
    """
    rng = np.random.default_rng(seed)
    base_mae = float(np.mean(np.abs(
        predict_price(model, pre.transform(raw).astype(np.float32)) - y_true
    )))
    eda_rho = load_eda_rho()
    features = []
    for column in raw.columns:
        values = raw[column].to_numpy()
        deltas = []
        for _ in range(n_repeats):
            shuffled = raw.copy()
            shuffled[column] = rng.permutation(values)
            mae = float(np.mean(np.abs(
                predict_price(model, pre.transform(shuffled).astype(np.float32)) - y_true
            )))
            deltas.append(mae - base_mae)
        entry = {
            "feature": column,
            "delta_mae_mean": float(np.mean(deltas)),
            "delta_mae_std": float(np.std(deltas)),
            "deltas": [float(d) for d in deltas],
        }
        if column in eda_rho:
            entry["eda_spearman_with_price"] = eda_rho[column]
        features.append(entry)
    features.sort(key=lambda f: -f["delta_mae_mean"])
    return {"split": "validation", "base_mae": base_mae, "n_repeats": n_repeats,
            "rows": int(len(raw)), "features": features}

    7 · Conclusion

    Was the network worth it? Stage 5 answers in one line: test MAE US$ 55.28 ± 0.08 over 5 seeds against Ridge's US$ 58.13, a gain of 4.90% where the Stage 0 criterion asked for 5%. The criterion was set before any network was trained and it was missed by US$ 0.06 of MAE. The gap to Ridge is nevertheless 34.6 times the standard deviation across seeds, so the improvement is real — it is simply smaller than what the team had decided would make the network worth adopting.

    Section 6B says where those 4.9% come from, and the answer sharpens the verdict: 18.0% and 18.9% in the US$ 60–130 bands, 9.5% at the bottom, and −1.0% in the most expensive fifth, where Ridge wins. The network buys accuracy on ordinary listings, in percentage terms, and gives a little back exactly where an error costs the most dollars. Against that: 211,457 parameters instead of 92, a PyTorch dependency, a training loop with early stopping, and a hyperparameter search over 19 configurations. For a team that wants a price hint for a typical listing, the network earns its place; for anyone who cares about the expensive end of the market, Ridge is the same model with none of the cost.

    Limitations.

    • The data is from 2019. It is a pre-pandemic snapshot of a market that has since changed in price level and in regulation; nothing here transfers to today without being refitted.
    • The listing text was dropped. name is the one column carrying words like "luxury", "penthouse" or "loft" — exactly the information missing to explain the tail that Sections 6B and 6C show the network cannot reach.
    • There is no outcome column. Nothing says whether a listing was ever booked, so a blocked calendar at US$ 10,000 and a real luxury apartment are identical to the model. Seven of the ten worst errors are of that kind.
    • Small subgroups are not measurable with this error distribution. Staten Island's MAE is 61% one listing; the Bronx's is 31% one listing. Any claim about a group of 73 rows, including the one in row 8 of the summary, is a claim about its worst listing.
    • The output is a point prediction with no interval, while the relative error ranges from 23.5% to 77.8% depending on the band.

    Who is affected by an error. The bias is not symmetric, so the harm is not either:

    • A host with an expensive listing is told to undercharge. In the US$ 199–10,000 band the bias is −162.48 on a mean price of 361.37; a host who prices from this model gives up real revenue every booked night.
    • A host with a cheap listing is told to overcharge, by +16.68 on a mean price of 47.36 — a 35% markup that can leave the calendar empty.
    • The smallest hosts are served worst. The model is least reliable where there are fewest listings: 65.6% relative error on Staten Island, 50.9% on Shared room, and the smallest gains over Ridge in the Bronx (0.8%) and Staten Island (2.9%). A tool built on this would work better for Manhattan apartments than for the hosts with the least room to absorb a bad night.
    • A guest reading a prediction as a fair price would judge nearly every expensive listing overpriced, since 193 of the 194 listings above US$ 500 are predicted below their price.

    What we would do with more time.

    1. Text features from name (TF-IDF or sentence embeddings) — the cheapest likely gain, given that the tail is the main source of error.
    2. An "is it active" proxy from reviews and availability, to flag or drop the placeholder listings that dominate the worst cases instead of training against them.
    3. Quantile regression, or a two-stage model that first classifies "tail", to report an interval instead of optimizing a single point for a distribution this skewed.
    4. Target encoding for neighbourhood instead of 76 one-hot columns, which would also make the importance of location readable in a single number rather than split across four columns.
